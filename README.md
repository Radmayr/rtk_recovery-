# rtk_recovery — проект по включению в реестр требований кредиторов

Расчёты по договорам клиентов-банкротов: сколько денег приходит после включения в РТК, по каким
договорам включение окупает госпошлину и сколько даёт отбор моделью. Функции для расчётов — в
библиотеке [collection_lab](https://github.com/Radmayr/collection_lab); здесь — сам проект:
отчёт, настройки и исследования.

```
rtk_recovery/
├── report/               отчёт для заказчиков
│   ├── rtk_report.ipynb          ноутбук отчёта (без результатов)
│   ├── run_report.py             выполнить и сохранить HTML без кода
│   ├── build_rtk_report.py       из него собирается ноутбук
│   └── settings_local.example.py пример настроек
├── research/             исследования выбора таргета (только локально, в git не попадают)
├── requirements.txt      зависимости: collection_lab и запуск ноутбуков
└── README.md
```

Данные, результаты и локальные настройки в git не попадают: в них рабочие цифры, пути и запросы.

## Отчёт «Включение в РТК: поступления, отбор договоров, эффект»

Одна HTML-страница без кода — цифры, графики и выводы.

- **Часть I.** Что происходит после включения в реестр: сколько денег приходит, когда, от каких
  договоров, как меняется по кварталам, сравнение продуктов.
- **Часть II.** Экономика включения с учётом госпошлины, модель «окупит ли договор пошлину»,
  винтажи по группам оценки модели (возвращают ли договоры с высокой оценкой больше), правило
  отбора и результат в деньгах — в целом и по каждому продукту.
- **Приложение.** Проверка данных: по каким продуктам нет транзакций или признаков.

### Запуск

```bash
git clone https://github.com/Radmayr/rtk_recovery-.git rtk_recovery && cd rtk_recovery
pip install -r requirements.txt

cp report/settings_local.example.py report/settings_local.py   # и поправить под себя
python report/run_report.py
```

Результат — в `report/out/`: `rtk_report.html` (для показа) и `rtk_report_executed.ipynb`.
Можно и без командной строки: открыть `report/rtk_report.ipynb` в Jupyter и выполнить все ячейки.

### Настройки

Все настройки — в первой ячейке ноутбука; файл `report/settings_local.py` выполняется поверх них,
поэтому ноутбук править не нужно.

| настройка | что задаёт | по умолчанию |
|---|---|---|
| `SOURCE` | откуда данные: `"csv"` — из файлов, `"query"` — запросом | `"csv"` |
| `TX_CSV`, `FEATURES_CSV` | пути к файлам транзакций и признаков | `data/df_1.csv`, `data/df_agg.csv` |
| `TX_QUERY`, `FEATURES_QUERY` | тексты запросов при `SOURCE = "query"` | — |
| `load_query(sql)` | функция, которая выполняет запрос и возвращает `DataFrame` | задать самому |
| `CACHE_DIR`, `REFRESH` | результат запросов сохраняется в папку и берётся оттуда при повторном запуске; `REFRESH = True` — перечитать из базы | `data_cache`, `False` |
| `PRODUCT` | продукт для подробного разбора в части I | `"PHX"` |
| `MODEL_PRODUCTS` | продукты для модели; `None` — все, по которым есть признаки, кроме продуктов с явными проблемами в данных | `None` |
| `RETRO_TO` | последняя дата включения в РТК; `None` — все договоры, у которых прошло 2 года | `None` |
| `OOT_FROM` | с какой даты включения договоры идут в проверочную выборку | `"2024-01-01"` |
| `DUTY_SHARE`, `OVERHEAD` | доля имущественной пошлины и расходы на подачу сверх неё, ₽ на договор | `0.5`, `0` |
| `MIN_CONTRACTS` | продукты с меньшим числом договоров на графики не выносятся | `100` |
| `SCORE_BUCKETS` | на сколько равных групп по оценке модели делить договоры для винтажей | `10` |
| `MODEL_PATH` | файл готовой модели (`.pkl` или `.txt` LightGBM); `None` — модель обучается в отчёте | `None` |
| `MODEL_FEATURES_JSON` | `features.json` готовой модели: списки `features` и `cat_features` | `None` |
| `SCORE_COL` | колонка с уже посчитанной оценкой в таблице признаков (вместо `MODEL_PATH`) | `None` |
| `MODEL_TARGET` | что предсказывает готовая модель — подставляется в текст отчёта | «договор вернёт больше 5 % долга за 2 года» |

### Какие данные нужны

**Транзакции** — строка на договор без транзакций либо на одну транзакцию. Обязательные колонки:
`contract_number`, `financial_account_subtype_cd` (продукт), `rtk_send_date`, `rtk_balance`,
`real_transaction_dttm`, `transaction_amt`.

**Признаки** — строка на договор: `contract_number` и колонки-признаки на дату включения. Всё,
кроме служебных колонок (`target`, `rtk_send_date`, `last_col_end_dt`, `job_organization_nm`),
идёт в модель.

### Готовая модель вместо обучения

По умолчанию отчёт сам обучает модель «окупит ли договор пошлину». Чтобы применить уже обученную,
задайте в `settings_local.py` одно из двух:

```python
# вариант 1: файл модели и список её признаков
MODEL_PATH = "/workdir/RTK_model/models/v_1/lgbm_final.pkl"
MODEL_FEATURES_JSON = "/workdir/RTK_model/logs/v_1/features.json"

# вариант 2: оценка уже посчитана и лежит колонкой в таблице признаков
SCORE_COL = "score"

OOT_FROM = "2024-03-01"   # не раньше, чем закончился период обучения модели
```

В этом режиме отчёт ничего не обучает: считает оценку (или берёт готовую), подбирает порог отбора
на более ранних договорах и показывает результат на проверочных. Сравнение с «текущей моделью» и
переобучение под сценарии затрат пропадают — под каждый сценарий меняется только порог.

- **Признаки модели** должны быть в таблице признаков под теми же именами — иначе отчёт остановится
  и назовёт недостающие колонки.
- **Подготовка признаков** по умолчанию: категориальные → `category`, остальные → число. Если модель
  обучалась на данных, подготовленных иначе, переопределите функцию `prepare_features(X, cat_features)`
  в `settings_local.py`.
- **`OOT_FROM`** должен быть не раньше конца обучения модели, иначе результат завышен.

### Как добавить другие продукты

1. Выгрузить транзакции и признаки по нужным продуктам — в те же две таблицы.
2. Запустить отчёт. Продукты, по которым есть признаки, попадут в модель сами; продукт станет
   одним из признаков.
3. В части II появится блок «Результат по продуктам»: включение по всем и отбор моделью по каждому
   продукту, а также сравнение общей модели с моделью только по основному продукту.

Продукты без транзакций и с поступлениями больше суммы долга в модель по умолчанию не идут —
это видно в приложении. Чтобы взять конкретный набор, задайте `MODEL_PRODUCTS = ["PHX", "CAR"]`.

### Что проверить после смены данных

- **Приложение в конце отчёта** — замечания по каждому продукту.
- **Тексты выводов.** Цифры в них подставляются из данных, а часть формулировок (например,
  «мелкие долги возвращают бóльшую долю») написана под текущую картину — перечитайте их.
- **`OOT_FROM`.** В проверочной выборке должно остаться достаточно договоров с истёкшими 2 годами.

### Как менять сам отчёт

Ноутбук собирается из `report/build_rtk_report.py` — правьте его и пересобирайте:

```bash
python report/build_rtk_report.py
```
